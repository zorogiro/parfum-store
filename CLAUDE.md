# Parfum Store

Tunisian e-commerce store selling perfumes, clothes and accessories. Guest checkout, cash on delivery only.

**The full plan is in `docs/mvp-plan.md`. Read it before starting any task** (it holds the data model, scope and the ordered task list).
Also read `AGENTS.md`: this Next.js version differs from older ones; check `node_modules/next/dist/docs/` before using framework APIs.

## Stack

Next.js (App Router, TypeScript, `src/`), Tailwind CSS v4, shadcn/ui, Prisma 7 + PostgreSQL (`@prisma/adapter-pg`), Zod, Auth.js (admin only, later), Cloudinary (images), Resend (email), Vitest (+ Playwright later), ESLint + Prettier.

## Conventions

- **Prices are integers in millimes** (1 TND = 1000 millimes). Never use floats for money. Format with `formatTND()` from `src/lib/money.ts` (e.g. `45,500 TND`).
- **Validate every server action with Zod** (schemas in `src/lib/validators`), and never trust prices or totals from the client. Admin actions and route handlers must call `requireAdmin()`.
- **No card data**, ever. **Cash on delivery only** in the MVP. No customer accounts.
- **French UI.** All user-facing text goes through `src/lib/strings.ts` (no hardcoded UI strings) so Arabic can be added later.
- **Admin auth** (Auth.js v5, JWT, credentials): `src/server/auth.ts` (`requireAdmin()`: call it first in every admin server action and route handler; the proxy is not enough), `src/server/auth.config.ts` (edge-safe config), `src/proxy.ts` (Next 16 name for middleware; guards `/admin/*`). Login attempts are limited by `loginRateLimiter` (`src/server/rate-limiters.ts`, Postgres-backed, fails CLOSED). The app refuses to start without `AUTH_SECRET`. All `/admin` pages are `noindex`; never add them to a sitemap. Admin panel pages live in `src/app/admin/(panel)/`; the login page is outside it.
- **Admin catalog** (`/admin/categories`, `/admin/products`): server actions in `src/server/categories.ts` and `src/server/products.ts` return `ActionResult` (`src/lib/action-result.ts`) instead of throwing; Zod schemas in `src/lib/validators/{category,product}.ts`. Admins type prices in TND; `parseTND()` / `toTNDInputValue()` in `src/lib/money.ts` convert to/from millimes. Slugs: `slugify()` / `uniqueSlug()` in `src/lib/slug.ts`. Variant `options` JSON is normalized per product type (PERFUME: volumeMl; CLOTHING: size + color; ACCESSORY: color). Categories are max 2 levels; deleting a category with products/subcategories is blocked; deleting a product that appears in orders soft-disables it (`isActive=false`). Image upload (Cloudinary) is not built yet (the cover column is a placeholder).
- **Product images** (Cloudinary): browser uploads directly with a signature from `getUploadSignature()` (`src/server/images.ts`, `requireAdmin()`); the API secret stays in `src/server/cloudinary.ts` (server-only). Images are saved with the product form (ordered list, first = cover); `publicId` must be `store/products/<id>` and the URL must be our cloud (`src/lib/cloudinary-validation.ts`). Files are deleted from Cloudinary best-effort (logged on failure) when removed on save or when the product is deleted.
- **Storefront** (`src/app/(shop)/`: `/`, `/c/[slug]`, `/search`, legal pages `/conditions-generales` `/confidentialite` `/retours`): only `isActive` products. URL params are parsed/whitelisted in `src/lib/catalog-query.ts` (`parseListingParams`, `buildFilterWhere`, `buildSearchWhere`, `buildListingHref`; params: `sort`, `page`, `min`/`max` in TND, `stock=1`, `brand`, `volume`, `size`, `color`; `q` for search). Cached queries (`"use cache"` + tag `catalog`/`settings`) live in `src/server/storefront.ts`; admin actions call `revalidateCatalog()` (does `updateTag("catalog")`), and the order flow must too when stock changes. Search is uncached and escapes LIKE wildcards. Price sorts sort in memory by lowest variant price. `ProductCard` data comes from `toProductCardData()` (`src/lib/product-card-data.ts`). - **Security rules (Task 9 review)**:
  - **CSP** is enforced (not report-only) from `next.config.ts` on every route, together with X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy and HSTS. It is static (no nonces: they would force dynamic rendering and defeat Cache Components), so `script-src` keeps `'unsafe-inline'` and has no `'unsafe-eval'` in production. `img-src` allows self, data:, blob:, res.cloudinary.com and placehold.co; `connect-src` allows self and api.cloudinary.com (direct image upload). Any new third-party script / image host / API origin (analytics, Sentry, a CDN) must be added to the CSP in `next.config.ts` and checked with `e2e/security.spec.ts`. Zod is told to skip its JIT in the browser (`src/lib/zod-config.ts`, imported by every validators module) because `new Function` would be blocked by the CSP.
  - **Rate limiting**: always use a limiter from `src/server/rate-limiters.ts` (`DbRateLimiter`, table `RateLimitBucket`, keys are HMACs so no IP/phone/email is stored in clear, window clock = database clock). Prefer `consume(key)` (atomic increment, returns allowed) over `isBlocked` + `recordFailure`. Customer paths (checkout, tracking, email) fail OPEN when the database is down; admin login fails CLOSED. `InMemoryRateLimiter` (`src/lib/rate-limit.ts`) is for unit tests only. New limiters go in `rate-limiters.ts` with an explicit `onError`.
  - **Emails**: `placeOrder` accepts any typed address, so the per-address cap (`customerEmailLimiter`) must stay. Never log recipients, names, phones or tokens.
  - **Logging**: server errors are logged with `logServerError()` (`src/server/log.ts`: error name + Prisma code only) or an equivalent that never prints messages, queries, request values or tokens. `src/server/token-exposure.test.ts` fails if a trackingToken reaches the admin UI, queries, emails, CSV or tracking result, or a log call.
  - **Errors**: friendly French boundaries (`src/app/error.tsx`, `global-error.tsx`, `(shop)/error.tsx`, `admin/(panel)/error.tsx`, shared `ErrorState`) never show messages or stack traces, only the opaque digest.
  - **SEO**: `src/app/sitemap.ts` (cached, tag `catalog`, home + categories + ACTIVE products + legal pages) and `src/app/robots.ts` (disallows /admin /cart /checkout /order /suivi /search); `/cart` and `/search` also send noindex.
  - **Accessibility** is guarded by `e2e/a11y.spec.ts` (axe WCAG A/AA, storefront), `e2e/admin-a11y.spec.ts` (axe + 390px, needs ADMIN_EMAIL/ADMIN_PASSWORD) and `e2e/keyboard.spec.ts` (focus trap, Escape, arrow keys on variant radios, visible focus). The write specs clear the `RateLimitBucket` table (dev DB only) because the limiter now lives in the database. Without the variable the writing ones are skipped. The Playwright web server sets `AUTH_TRUST_HOST=true` (Auth.js refuses unknown hosts in production mode).

Don't use `usePathname()` in shop header components outside Suspense.
- **Session rule**: never run `taskkill /IM node.exe`, `pkill node` or anything that kills all Node processes. Only stop the dev/start server you started yourself, by its PID.
- Prisma client is generated to `src/generated/prisma`; import the shared instance from `@/lib/db`.
- Prisma 7: connection URLs live in `prisma.config.ts` (CLI uses `DIRECT_URL`); the app uses the pooled `DATABASE_URL` via the pg adapter. Order numbers come from `nextOrderNumber(tx)` in `src/server/order-number.ts` (Postgres sequence `order_number_seq`); call it inside the order-creating transaction.

- `src/app` routes (App Router)
- `src/components` React components (`ui/` = shadcn)
- `src/lib` db, utils, money, strings, `validators/`
- `src/server` server actions and services
- `prisma/` schema, migrations, seed
- `docs/` plan and deployment docs

## Commands

- `npm run dev` dev server
- `npm run build` production build
- `npm run lint` ESLint
- `npm run typecheck` TypeScript check
- `npm test` Vitest (unit)
- `npm run test:e2e` Playwright (cart smoke is read-only; the checkout spec writes and is skipped without `E2E_ALLOW_DB_WRITES=1`; starts its own server on port 3100 from the last `npm run build`, needs the seeded DB)
- `npm run format` Prettier
- `npm run db:migrate` Prisma migrate dev
- `npm run db:seed` run `prisma/seed.ts` (needs `ADMIN_EMAIL` / `ADMIN_PASSWORD`; idempotent)
- `npx tsx scripts/verify-db.ts` print row counts of the seeded tables
